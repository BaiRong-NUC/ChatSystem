# QtChatClient 协议与接口说明

本文档用于说明 QtChatClient 与服务端之间的通信协议、接口约定与消息流转设计。

## 1. 当前状态

截至目前，客户端代码中尚未接入完整的网络通信与业务接口实现，因此本文件当前以“预留结构 + 已知约束 + 后续补充点”为主。

本文件暂不声称已有可用协议实现。

## 2. 未来建议覆盖范围

当客户端与服务端联调开始后，本文件应至少覆盖以下内容：

1. 连接建立方式。
2. 登录、登出接口。
3. 拉取会话列表接口。
4. 拉取历史消息接口。
5. 发送文本消息接口。
6. 发送图片、文件、语音消息接口。
7. 好友列表、好友申请相关接口。
8. 错误码与异常响应格式。

## 3. 可先确定的数据约束

即使网络协议尚未落地，当前数据模型已经对协议字段提出了一些约束：

1. 用户侧至少需要用户 ID、用户名、签名、手机号、头像等信息。
2. 会话侧至少需要会话 ID、会话名称、最后一条消息、会话头像、关联用户 ID。
3. 消息侧至少需要消息 ID、发送者、所属会话 ID、时间戳、消息类型、消息体、附件 ID、文件名。
4. 消息类型当前已固定为 Text、Image、File、SPEECH 四类。

## 7. 添加朋友窗口的客户端契约

`AddFriendWidget` 已提供手机号或用户 ID 的统一搜索入口，但当前仓库尚未接入服务端查询实现。

1. 用户提交非空关键字后，窗口发出 `searchUserRequested(keyword)`；业务层应同时按手机号和用户 ID 精确查询。
2. 查询开始后，窗口进入“搜索中”状态。业务层必须调用 `showSearchResult`、`showNoSearchResult` 或 `showSearchError` 结束该状态。
3. 搜索结果中的“添加”按钮发出 `addFriendRequested(userId)`，业务层处理完成后调用 `showFriendRequestResult` 回填结果。
4. `MainWidget` 会转发两个业务信号，并提供对应的搜索结果和申请结果回填方法，便于后续 Controller 或 Service 接入。
